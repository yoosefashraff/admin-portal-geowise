# Git Repository Safety Rules

## ⚠️ CRITICAL: Never Push to the Wrong Repository

This project uses a **dual-repository setup** for different deployment targets. Pushing to the wrong repository can cause:
- Code deployed to wrong environment
- Netlify deployments breaking
- Company server deployments failing
- Data loss or security issues

## Repository Mapping

| Remote | Repository | Purpose | Branches |
|--------|-----------|---------|----------|
| **`upstream`** | `GeoWise-AI/company-admin-portal` | **Company server deployments** | `master` (main), `dev`, `twitchers`, `feature/*` |
| **`origin`** | `yoosefashraff/company-admin-portal` | **Netlify deployments** | `netlify` (main branch, auto-synced) |

## Mandatory Safety Rules

### 1. Always Use Explicit Remote Names

✅ **CORRECT:**
```bash
git push upstream feature/task-description
git push upstream dev
git push upstream master
```

❌ **WRONG:**
```bash
git push origin feature/task-description  # Pushes to personal repo!
git push  # May push to wrong default remote!
```

### 2. Verify Remotes Before Pushing

**ALWAYS run this before pushing:**
```bash
git remote -v
```

Expected output:
```
origin    https://github.com/yoosefashraff/company-admin-portal.git (fetch)
origin    https://github.com/yoosefashraff/company-admin-portal.git (push)
upstream  https://github.com/GeoWise-AI/company-admin-portal.git (fetch)
upstream  https://github.com/GeoWise-AI/company-admin-portal.git (push)
```

### 3. Branch-to-Remote Mapping

| Branch | Push To | Purpose |
|--------|---------|---------|
| `feature/*` | `upstream` | Feature development |
| `dev` | `upstream` | Dev server deployment |
| `master` | `upstream` | Production deployment |
| `twitchers` | `upstream` | Twitchers deployment |
| `netlify` | **AUTO-SYNCED** | Netlify deployment (GitHub Actions) |

### 4. When to Use Each Remote

**Use `upstream` (GeoWise repo) for:**
- ✅ All feature branches
- ✅ `dev` branch
- ✅ `master` branch
- ✅ `twitchers` branch
- ✅ Any company-related work

**Use `origin` (personal repo) for:**
- ❌ **NEVER** for company work
- ⚠️ Only for rare manual backups (explicitly requested)
- ✅ The `netlify` branch is the **main branch** on personal repo and is **automatically synced** by GitHub Actions - don't push manually

### 5. Pre-Push Checklist

Before executing ANY `git push` command:

- [ ] Ran `git remote -v` to verify remotes
- [ ] Confirmed using `upstream` for company work
- [ ] Verified branch name matches deployment target
- [ ] Not pushing to `origin` unless explicitly backing up
- [ ] Double-checked the remote name in the command

## Common Mistakes to Avoid

### ❌ Mistake 1: Pushing feature branch to origin
```bash
git push origin feature/task  # WRONG!
```
**Impact:** Code goes to personal repo, not company repo. Deployment won't trigger.

### ❌ Mistake 2: Using default push
```bash
git push  # WRONG - may push to wrong remote!
```
**Impact:** Could push to `origin` if it's the default, breaking Netlify deployments.

### ❌ Mistake 3: Pushing master/dev to origin
```bash
git push origin master  # WRONG!
```
**Impact:** Overwrites netlify branch, breaks Netlify deployment, doesn't deploy to company server.

## Verification Commands

### Check current remotes
```bash
git remote -v
```

### Check which remote a branch tracks
```bash
git branch -vv
```

### Check what would be pushed
```bash
git push --dry-run upstream <branch>
```

### Verify branch exists on correct remote
```bash
git ls-remote upstream <branch>
git ls-remote origin <branch>
```

## Emergency Recovery

If you accidentally pushed to the wrong repository:

1. **Don't panic** - the damage is usually reversible
2. **Check what was pushed:**
   ```bash
   git log origin/<branch>  # See what went to personal repo
   git log upstream/<branch>  # See what's on company repo
   ```
3. **Revert if needed:**
   ```bash
   # If pushed to origin by mistake, push correct version to upstream
   git push upstream <branch>
   ```
4. **Notify the team** if production was affected

## Automation Safety

- **GitHub Actions** automatically syncs `master`/`dev` → `netlify` branch on personal repo
- **Never manually push to `netlify` branch** - let automation handle it
- **If sync fails**, check GitHub Actions logs, don't manually fix by pushing to origin

## Remember

> **When in doubt, use `upstream` for company work.**
> 
> **When in doubt, verify with `git remote -v` before pushing.**
> 
> **When in doubt, ask before pushing to `origin`.**
